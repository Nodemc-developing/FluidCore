# 兼容矩阵

作者及维护者：ydxc20091。当前源码以 Paper/Folia 1.21—26.3、CraftEngine 26.9.2 及已有 26.10 API 为目标；全部自研模块及随包依赖均可由 Java 21 加载。1.21.x 服务端使用 Java 21，26.x 服务端使用 Java 25。已发布的 Build 2 仍是 Java 25 制品，不能把本次源码修改当作旧发布文件的能力。兼容性由固定服务端上的实际行为验证确定；插件元数据和编译成功本身不构成运行验收。

## 构建兼容策略（2026-10-07）

FluidCore 运行时原本没有 CE 文件哈希白名单。本轮移除 Gradle 对两个具体 CE SHA256 的限制和按哈希选择原生编译依赖的逻辑，改为插件元数据版号与必要 API 入口检查；实际方法签名由编译器验证。26.9.2 支持同版本的 `-suffix`／`+build` 标记，`26.9.20` 不会误当 26.9.2；保留 26.10 路径，不扩展其他未知版本系列。校验值继续保留在原始报告及制品清单，用于说明实际测过哪个文件，不作为兼容门槛。

CE 的公共 API 说明见 [官方 API 文档](https://xiao-momi.github.io/craft-engine-wiki/api/) 和 [官方仓库](https://github.com/Xiao-MoMi/craft-engine)。上游区分稳定 Bukkit API 与不稳定的 NMS／proxy 接口；版本相同的额外构建不自动继承本项目固定场景的运行验收结果。储罐桥的原有 API 能力检查继续生效，没有新增运行时文件读取或哈希限制。

本轮实际执行 13 项构建校验场景，覆盖同版本不同内容、构建后缀、错误版本边界及缺失接口；它们是元数据／API 入口夹具，不模拟原生服务端。未变的 221 项平台和 73 项 core 测试及编译结果由 Gradle 匹配缓存恢复；产出的运行 JAR 与已验收 Build 3 完全相同。原始检查记录见 [构建策略验证](../verification/results/ce-api-build-compatibility-2026-10-07.json)，未为本轮新增启服或真人运行结论。

## 支持版本、验收依赖与场景

CraftEngine 稳定支持版本为 **26.9.2**，并保留 **26.10** 原生能力路径。历史验收使用的 26.9.2 文件 SHA256 为 `1f9e0935a11e7d6c7a979f2d521ec24efb715375c876a57ef3cc11e9fb9895aa`，26.10-SNAPSHOT 文件为 `46ebe45f31f3e3f0965179a85cb1f308d8729f53281d6c64f4ef2af5c23d99f6`。这些哈希只标识验收输入；同版本且具备必要 API 的其他文件可以构建与加载，仍须区分其实际运行验证范围。

26.10 使用 CE 真正的睡眠 ticker 与邻接区块订阅；睡眠实体进入 CE 的非活跃列表。26.9.2 没有该 API，使用相同唤醒时机的软件 ticker gate，睡眠时不执行业务，但 CE 仍会检查这一轻量入口；跨区块邻接通过按目标区块索引的加载事件通知，在储罐所属线程唤醒。加载阶段只选取一次适配器，业务点击与 tick 不使用反射。

构建同一兼容制品时，传入稳定 `-PceJar=...` 与快照 `-PceNativeJar=...`。验证快照运行依赖可使用 `:paper-ce:test -PceTestRuntime=snapshot`；只替换测试运行 classpath，业务源码仍按稳定基线编译。

Sparrow UI 依赖仅支持 Minecraft 1.21.4 及以上；1.21—1.21.3 的储罐使用 Bukkit 箱子界面后端，复用相同事务与配方返回流程，普通背包操作沿用原版。早期版本仍禁用额外图形诊断，可使用 `/fluidcore inspect`。所有版本均未完成本次真人 GUI 操作验收。

1.21—1.21.3 保留 CE 的原有整数 CustomModelData 与物品模型，流体、容量和玻璃颜色数据正常保存；这些客户端没有 1.21.4 的结构化多颜色模型。新版双色渲染与动态 `item_model` 仅在 1.21.4 及以上启用，早期版本需要内容包提供自己的旧模型映射。皮革物品原有的液体染色继续保留。

每次验收记录服务端名称、Minecraft 版本、构建号或服务端 JAR 校验值、Java 完整版本、CE 与 FluidCore JAR 校验值及覆盖场景。通过状态只适用于指定构建，不自动扩展到后续快照。

“标准 API＋完整场景＋重启”包括程序化 CE 放置、实际 loot 掉落和重新放置、流体模拟与执行、controller 保存／加载、真实 ItemStack／PDC 和槽位替换、零 ticker 储罐、处理器睡眠唤醒、所属区域检查及停止／重启后的内容恢复。真人客户端菜单、保护插件组合和其他交互路径另行验收。

服务端运行要求见 [Paper Java 文档](https://docs.papermc.io/paper/getting-started/)。当前推荐版本可能变化，本项目结果以固定构建为准。
