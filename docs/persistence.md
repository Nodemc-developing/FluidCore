# 持久化契约

流体编码使用 `FCOR` magic、版本字段与 CRC32C 尾部校验，不依赖 Java 对象序列化或 CE 内部对象的稳定布局。流体标识、数量和组件完整保存。组件为带命名空间的不可变字节值，类型解释由显式编码器负责；未知组件保留原始值，不执行未知类。

迁移只接受已知旧版本，升级失败保留原始载荷。损坏、超大、截断或未来版本输入返回明确失败，不清空原始容器。默认总大小上限 1 MiB、每个 key UTF-8 上限 512 字节、组件上限 256 个，输入超限时拒绝。

容量缩小或过滤变严格时，已有内容不得静默丢失。保持旧有效内容可抽取，禁止不符合新约束的新增；需要人工迁移的状态在诊断中显示。物品和方块应保存相同身份数据，放置、破坏、掉落与重新放置不能丢失组件。

CE 桥接使用 block entity controller 的公开保存／加载入口；物品使用 `fluidcore` 命名空间。内存事务成功后再标脏和触发更新。玩家数据与区块数据分开写入，服务器崩溃时不保证两者一起落盘。

独立本库配置和 `fluidcore:fluids` 候选失败保留旧快照，不能据此推导整个 CE pack 在重载时一起回滚。item、block 及其他 CE 内容仍由 CE 自己决定重载结果。
